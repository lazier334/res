# 插件系统

[LazierServer](https://github.com/lazier334/LazierServer) 的插件系统是项目的核心扩展机制，允许开发者通过编写插件来添加新功能。

## 插件架构

### 阶段化设计

插件系统采用阶段化架构，每个阶段负责特定的功能，你可以自由的创建自定义的阶段，当调用 `plugins('{阶段名}')` 的时候会去所有的插件目录扫描该阶段的所有插件，由于没有分割符，所以阶段名字建议超过4个字符，避免重名，例如 abcd*.js 和 ab*.js 重名，调用 ab 阶段的时候会把 abcd 阶段一起调用。


## 插件类型

LazierServer 提供多种插件类型，每种类型对应不同的功能场景。

### 插件类型概览

| 类型                | 文件名格式                | 功能           | 执行时机        |
| ------------------- | ------------------------- | -------------- | --------------- |
| systemStart         | `systemStart*.js`         | 系统启动初始化 | 服务器启动时    |
| koaPlugin           | `koaPlugin*.js`           | Koa中间件      | 每个请求        |
| koaRouter           | `koaRouter*.js`           | 路由定义       | 路由匹配时      |
| indexData           | `indexData*.js`           | 首页数据       | 首页请求时      |
| websocketMsgs       | `websocketMsgs*.js`       | WebSocket消息  | WebSocket连接时 |
| websocketApis       | `websocketApis*.js`       | WebSocket接口  | WebSocket消息时 |
| send                | `send*.js`                | 文件发送处理   | 文件发送前      |
| selectFileByDomains | `selectFileByDomains*.js` | 域名选择       | 多域名匹配时    |

### 详细说明

#### 1. systemStart - 系统启动插件

**用途**: 服务器启动时执行，用于初始化配置、日志、监控等。

**执行时机**: 服务器启动时，只执行一次。

**参数**:
```typescript
{
    fs: typeof import('fs'),
    path: typeof import('path'),
    config: ConfigType,
    app: Koa
}
```

**示例**:
```javascript
import { createSystemStart } from 'lazierserver/types';

export default createSystemStart(async function({ fs, path, config, app }) {
    // 初始化日志系统
    console.info('服务器启动中...');
    
    // 监控配置文件
    chokidar.watch(config.ldConfigPath).on('change', () => {
        console.log('配置文件已更新');
    });
});
```

**内置插件**:
- `systemStart-0-logger.js` - 日志系统初始化
- `systemStart-1-common.js` - 通用初始化
- `systemStart-2-addAppStack.js` - 堆栈追踪

#### 2. koaPlugin - Koa中间件插件

**用途**: Koa中间件，处理请求和响应。

**执行时机**: 每个HTTP请求都会执行。

**参数**:
```typescript
(ctx: Koa.Context, next: Koa.Next) => Promise<void>
```

**示例**:
```javascript
import { createKoaPlugin } from 'lazierserver/types';

export default createKoaPlugin(async function(ctx, next) {
    // 请求前处理
    const startTime = Date.now();
    
    // 执行下一个中间件
    await next();
    
    // 响应后处理
    const duration = Date.now() - startTime;
    console.log(`${ctx.method} ${ctx.url} ${ctx.status} ${duration}ms`);
});
```

**内置插件**:
- `koaPlugin-2-cors.js` - CORS跨域
- `koaPlugin-2.1-autoCors.js` - 自动CORS跨域-用于关闭跨域限制
- `koaPlugin-3-bodyparser.js` - 请求体解析
- `koaPlugin-4-counter.js` - 请求计数
- `koaPlugin-5-sw.js302Fix.js` - Service Worker修复
- `koaPlugin-6-rewritePathnameToIndex.html.js` - 路径重写
- `koaPlugin-7-proxies.js` - 请求代理
- `koaPlugin-8-session.js` - 会话管理

#### 3. koaRouter - 路由插件

**用途**: 定义API路由和接口，可以通过 `/** @type {ctx & T} */ const ectx = ctx;` 用于获取完整提示信息

**执行时机**: 路由匹配时。

**参数**:
```typescript
(router: Router, types: extendTypes) => PluginResult
```

**示例**:
```javascript
import { createKoaRouter } from 'lazierserver/types';

export default createKoaRouter(function(router, T) {
    // GET接口
    router.all('接口说明: 获取数据', '/api/data', async (ctx) => {
        ctx.body = { data: '示例数据' };
    });
    
    // POST接口
    router.all('接口说明: 创建数据', '/api/create', async (ctx) => {
        const { name } = ctx.request.body;
        ctx.body = { code: 200, msg: '创建成功' };
    });
    
    // 正则路由
    router.all('接口说明: 动态路由', /^\/api\/user\/(\d+)$/, async (ctx) => {
        const userId = ctx.params[0];
        ctx.body = { userId };
    });
    
    // 在扫描到静态资源文件 demo.txt 之后对其进行处理。其中的 `/** @type {ctx & T} */` 用于获取完整提示信息
    // 以下将读取 demo.txt 文件改成读取 _demo.txt 文件。这样就能提前处理原始的 demo.txt 文件了
    // 如果是需要自定义响应内容，直接修改 ctx.body 不为 undefined 即可
    router.all('/demo.txt', async (ctx, next) => {
        /** @type {ctx & T} */
        const ectx = ctx;
        ectx.sendOptions.filename = '_' + ectx.sendOptions.filename;
        console.log(ectx.sendOptions.filename)
    });
    
    return router;
});
```

**内置插件**:
- `koaRouter-1-scanHar.js` - HAR文件扫描
- `koaRouter-1.1-scanWeb.js` - Web资源扫描
- `koaRouter-2-editWebDemo.js` - Web编辑示例
- `koaRouter-3-other.js` - 其他接口
- `koaRouter-4-pluginManagement.js` - 插件管理
- `koaRouter-4-system.js` - 系统接口
- `koaRouter-5-history.js` - 历史路由
- `koaRouter-5-uploads.js` - 文件上传
- `koaRouter-6-im.js` - 即时通讯
- `koaRouter-7-rpc.js` - RPC接口(未使用，大概率不完整)

**参数**:


**内置插件**:

#### 5. websocketMsgs - WebSocket消息插件

**用途**: WebSocket连接时自动响应的消息。

**执行时机**: WebSocket客户端连接时。

**参数**:
```typescript
(arr: MsgArray) => PluginResult
```

**消息格式**:
```typescript
{
    type: 'send' | 'receive',
    time: number,
    opcode: number,
    data: string | Uint8Array,
    step: number // 该字段是和上一条消息的间隔时间(ms)
}
```

**示例**:
```javascript
import { createWebsocketMsgs } from 'lazierserver/types';

export default createWebsocketMsgs(async function(arr) {
    arr.push({
        type: 'receive',
        time: Date.now(),
        opcode: 2,
        data: JSON.stringify({ message: '欢迎连接' }),
        step: 0
    });
    
    return arr;
});
```

#### 6. websocketApis - WebSocket接口插件

**用途**: 处理WebSocket消息的API，系统会预处理，先将 message 转成字符串，然后再使用 JSON.parse 尝试把 message 字符串转成 json 对象

**执行时机**: 收到WebSocket消息时。

**参数**:
```typescript
(msg: string | Buffer, message: Buffer, ws: WebSocket, req: IncomingMessage) => PluginResult
```

**示例**:
```javascript
import { createWebsocketApis } from 'lazierserver/types';

export default createWebsocketApis(async function(msg, message, ws, req) {
    try {
        switch (msg.type) {
            case 'ping':
                ws.send(JSON.stringify({ type: 'pong', time: Date.now() }));
                break;
                
            case 'message':
                console.log('收到消息:', msg.content);
                ws.send(JSON.stringify({ type: 'echo', content: msg.content }));
                break;
        }
    } catch (error) {
        console.error('WebSocket消息处理错误:', error);
    }
    
    return { end: false };
});
```

**内置插件**:
- `websocketApis-1-im.js` - 即时通讯接口
- `websocketApis-2-uplogs.js` - 上传日志接口

#### 7. send - 文件发送插件

**用途**: 处理文件发送前的逻辑，这是每个文件发送都会走的处理，使用api的方式只能拦截对应的api。

**执行时机**: 文件发送前。

**参数**:
```typescript
(sendOptions: SendFileType) => Promise<boolean | SendFileType>
```

**示例**:
```javascript
import { createSend } from 'lazier334/types';

export default createSend(async function(sendOptions) {
    const { ctx, filename, opts } = sendOptions;
    
    // 检查文件权限
    if (filename.startsWith('private')) {
        ctx.status = 403;
        ctx.body = '禁止访问';
        return true; // 已处理，不再继续
    }
    
    // 修改文件名
    if (filename.endsWith('.txt')) {
        sendOptions.filename = 'processed_' + filename;
    }
    
    return sendOptions; // 继续处理
});
```

**内置插件**:
- `send-redirectApi.js` - 重定向API
- `send-sameApi.js` - 相同API处理

#### 8. selectFileByDomains - 域名选择插件

**用途**: 多个域名文件夹存在同一API文件时的选择算法。

**执行时机**: 多个目录存在相同文件时。

**参数**:
```typescript
(domains: string[], domainsMap: object, ctx: Koa.Context) => { end: boolean, result: string }
```

**示例**:
```javascript
import { createSelectFileByDomains } from 'lazier334/types';

export default createSelectFileByDomains(function(domains, domainsMap, ctx) {
    // 根据条件选择域名
    const selectedDomain = domains.find(d => d.includes('production')) || domains[0];
    
    return { 
        end: true, 
        result: selectedDomain 
    };
});
```

### 类型定义

#### PluginResult 动态插件返回值
> 文件位于: ld/lazier334/types/plugins.ts

```typescript
type PluginResult = {
    /* 是否提前结束插件 use 调用，返回true则不会再继续使用后面的动态插件进行处理 */
    end: boolean;
    /* 配合 end 字段使用，结束时使用该内容作为响应结果 */
    result: void;
}
```

#### SendFileType
> 文件位于: ld/lazier334/koaRouter-1.1-scanWeb.js#L158

```typescript
type SendFileType = {
    sendFileFromPath?: string;
    sendOptions: {
        ctx: Koa.Context;
        filename: string;
        opts: SendOptions;
        editTag: string;
        newFilepath: string | null;
        sendBefore: () => Promise<void>;
        sendAfter: (error?: any) => Promise<void>;
        send: () => Promise<any>;
    };
}
```

#### SendEntryType
> 文件位于: ld/lazier334/koaRouter-1-scanHar.js#L66

```typescript
type SendEntryType = {
```

## 常见问题

### 插件不生效

1. 检查文件命名是否符合规则
2. 确认插件目录已添加到配置
3. 查看服务器日志

### 路由冲突

1. 使用更具体的路由路径
2. 调整插件序号改变执行顺序
3. 使用不同的路由方法

### 性能问题

1. 减少同步操作
2. 使用缓存
3. 优化数据库查询
